1. 项目目标

该项目的目标是把船舶加油原始记录从多行事件表整理为 transaction level 数据：每一行代表一次加油交易，保留船舶信息、整段过程时间、每一次 STS 加油事件、supplier、加油港口、吃水变化等字段。随后，以每笔交易的 startdate、starthour 和 port 为锚点，在 Stata 中匹配小时级锚地开放状态与气象预报指数，生成交易层面的历史开放时长与预测开放时长。

执行分工：交易记录清洗、字段解析、模糊港口匹配、多 STS 展开、去重和质检用 Python 完成；锚地开放与气象预报的前后窗口匹配用 Stata 完成。

3. 目标交易层数据结构

Python 阶段建议输出 outputs/transactions_clean.xlsx，并额外输出可审查的长表与问题样本表，例如 outputs/sts_episode_long.xlsx、outputs/unmatched_ports.xlsx、outputs/port_conflicts.xlsx。核心交易层字段如下。

3.1 船舶与交易标识字段

字段 含义 生成规则
transaction_id 交易唯一编号。 若源 sheet 已有则沿用；否则按非空 vessel 行累积生成。
vessel_name、imo、vessel_type、service_status、dwt、gt 船舶基础信息。 从 vessel 字符串中解析，例如 JOLLY ARGENTO (9467043) - Container Ship, In Service/Commission, 62510 dwt, 47789gt。
draught_numeric 吃水变化数值。 从 ± Draught 中提取数值，例如 +0.1 m 转为 0.1。

3.2 整段过程时间字段

字段 含义 口径
startdate、starthour 该 transaction 整个过程的开始日期与小时。 取该交易所有事件 Start 的最早值，按四舍五入到小时后再拆分日期和小时。
enddate、endhour 该 transaction 整个过程的结束日期与小时。 取该交易所有事件 End 的最晚值，按四舍五入到小时后再拆分日期和小时。
duration 整个过程时长，单位小时。 用最晚原始 End 减最早原始 Start，以小时为单位四舍五入。

3.3 多 STS 与 supplier 字段

每笔 transaction 可能出现多个 supplier，或同一 supplier 出现多条 STS。处理时必须把每一次 STS 按时间顺序拆开记录。

字段模式 含义 说明
start_STS1、end_STS1、duration_STS1 第 1 次 STS 的开始、结束与时长。 按 STS 开始时间排序。start_STS* 与 end_STS* 建议存完整四舍五入后 datetime；duration_STS* 用原始起止时间差四舍五入到小时。
start_STS2、end_STS2、duration_STS2，依此类推 后续 STS 事件。 最大编号由全样本中一笔交易的最大 STS 条数决定。
supplier1、supplier2，依此类推 每次 STS 对应的 supplier。 从 STS 行的 Location Details 提取，例如 With Fu Jie 168 转为 Fu Jie 168。若同一个 supplier 有多条 STS，则多个 supplier 字段可以相同。
supplier_n 该 transaction 中 STS/supplier 记录数。 按 STS episode 计数，不按唯一 supplier 去重；如同一 supplier 出现两条 STS，则 supplier_n = 2。
duration_STS 总加油时长，单位小时。 等于 duration_STS1 + duration_STS2 + ...。
end_STS_final、endhour_STS_final 最后一个 supplier/STSes 加油结束日期与小时。 取最后一条 STS 的 End，按小时四舍五入后拆分日期与小时。
待审查口径：supplier_n 在本文档中定义为 STS episode/supplier 记录数，而不是唯一 supplier 数。若后续研究需要唯一 supplier 数，可额外生成 supplier_unique_n 作为辅助变量。

4. 核心处理规则

4.1 Operations 识别

  • Operations 包含 STS - Bunkering 的行视为加油事件。
  • Operations 包含 Anchorage 的行视为排队等待或锚地相关事件。
  • 一笔 transaction 可以同时包含多条 Anchorage 和多条 STS。

4.2 时间四舍五入规则

所有需要落到小时的时间，都先对完整 datetime 四舍五入，再拆分日期和小时。关键是处理跨日情形：2024/1/5 23:42 应转为 2024/1/6 00:00，而不是 2024/1/5 00:00。 

def round_to_hour(dt):
    # 先给完整 datetime 加 30 分钟，再 floor 到小时。
    # 这样 23:42 会自然进入下一天 00:00。
    return (dt + pd.Timedelta(minutes=30)).floor("h")

4.3 港口识别与模糊匹配

只有出现在对照表中的港口才视为加油港口。若同一交易下所有 Location Details 均无法匹配到对照港口，则 port 留空，后续可删除或单独复核。若同一交易中有多个描述，其中一个可匹配、另一个不可匹配，则保留可匹配港口。

英文/模糊名称 输出 port 说明
Zhoushan Tide and Berth Waiting Anchorage、Zhoushan East Anchorage、Xiushan East等 秀山东 PDF 中对应 Xiushan East；Excel 样本中也出现 East Anchorage。
Zhoushan Mashi Anchorage、No1/No2/Dangerous Goods、Mazhi等 马峙 包括马峙锚地相关变体。
Zhoushan Xiazhimen South Anchorage、Xiazhimen So、Xiazhimen Sou、Xiazhimen South等 条帚门 用户明确指出 At Zhoushan Xiazhimen Sou 应识别为 Zhoushan Xiazhimen South Anchorage。
Zhoushan Xiazhimen North Anchorage、Xiazhimen North等 虾峙门 北锚地。
Zhoushan Qushan Bunkering Anchorage、Qushan等 衢山 与 锚地开放.dta、气象预报.dta 中的中文港口名保持一致。
冲突处理建议：若同一 transaction 匹配出多个不同的对照港口，应保留一个确定性结果并生成 port_conflict_flag = 1 供人工复核。建议默认取交易内最早出现的可匹配港口，或优先取与 STS 最近的 Anchorage 港口；该口径应在正式跑数前确认。

4.4 去重与核对

  • 删除重复交易记录前，应先保留 duplicate_flag 与去重 key，便于审查。
  • 推荐去重 key：imo、交易起止时间、port、STS 起止序列、supplier 序列。
  • 最终必须比对原始数据：交易数量、STS 行数、supplier 提取数、匹配到 port 的交易数、未匹配 port 样本。

5. Python 可执行步骤

Python 阶段的目标是把 Excel 多行事件数据整理成交易层主表，并生成复核用长表。建议脚本命名为 scripts/process_transactions.py，输出均写入工作目录下的 outputs/。

P0. 建立目录与配置 工作目录 设置输入文件名、源 sheet 名、输出目录、港口对照正则。 outputs/ 存在；日志记录脚本配置。
P1. 读取并标准化 Excel Bunkering Record v3.xlsx 定位表头行，统一列名，丢弃完全空行。 输出原始有效行数、识别出的列名。
P2. 交易编号与 vessel 填充 标准化事件表 若有 transaction_id 则沿用；否则以非空 vessel 行为新交易起点生成编号。对交易内空白 vessel 向下填充。 每行均有 transaction_id 与 vessel 字符串。
P3. 解析船舶字段 vessel 字符串 提取船名、IMO、类型、服务状态、DWT、GT。 输出解析失败样本，避免静默丢失。

Python 代码框架

from pathlib import Path
import re
import pandas as pd
import numpy as np

ROOT = Path(".")
INPUT_XLSX = ROOT / "Bunkering Record v3.xlsx"
OUT = ROOT / "outputs"
OUT.mkdir(exist_ok=True)

SOURCE_SHEET = "Bunkering Raw Data V2"  # 如正式使用 Sheet1，可改为 "Sheet1"

PORT_PATTERNS = [
    (re.compile(r"(tide and berth waiting|xiushan east|east anchorage)", re.I), "秀山东"),
    (re.compile(r"(mashi|ma\s*shi|mazhi|dangerous goods|no1|no2)", re.I), "马峙"),
    (re.compile(r"(xiazhimen\s*(south|so|sou)|xiazhimen south)", re.I), "条帚门"),
    (re.compile(r"(xiazhimen\s*north|xiazhimen north)", re.I), "虾峙门"),
    (re.compile(r"(qushan)", re.I), "衢山"),
]

def round_to_hour(dt):
    if pd.isna(dt):
        return pd.NaT
    return (dt + pd.Timedelta(minutes=30)).floor("h")

def parse_datetime_series(s):
    # pandas 可同时处理 Excel datetime 与常见英文日期字符串；无法解析的值保留 NaT 并进入 QA。
    return pd.to_datetime(s, errors="coerce")

def parse_vessel(v):
    text = "" if pd.isna(v) else str(v).strip()
    pattern = re.compile(
        r"^(?P<name>.*?)\s*\((?P<imo>\d+)\)\s*-\s*"
        r"(?P<type>.*?),\s*(?P<status>.*?),\s*"
        r"(?P<dwt>[\d,]+)\s*dwt,\s*(?P<gt>[\d,]+)\s*gt",
        re.I
    )
    m = pattern.search(text)
    if not m:
        return pd.Series({
            "vessel_name": np.nan, "imo": np.nan, "vessel_type": np.nan,
            "service_status": np.nan, "dwt": np.nan, "gt": np.nan
        })
    d = m.groupdict()
    return pd.Series({
        "vessel_name": d["name"].strip(),
        "imo": d["imo"],
        "vessel_type": d["type"].strip(),
        "service_status": d["status"].strip(),
        "dwt": int(d["dwt"].replace(",", "")),
        "gt": int(d["gt"].replace(",", "")),
    })

def extract_supplier(location_details):
    text = "" if pd.isna(location_details) else str(location_details).strip()
    text = re.sub(r"^\s*with\s+", "", text, flags=re.I)
    return text.strip() or np.nan

def match_port_one(text):
    if pd.isna(text):
        return None
    text = str(text)
    for pattern, port in PORT_PATTERNS:
        if pattern.search(text):
            return port
    return None

def choose_transaction_port(details):
    matched = [p for p in (match_port_one(x) for x in details.dropna()) if p]
    unique = list(dict.fromkeys(matched))
    if not unique:
        return pd.Series({"port": np.nan, "port_conflict_flag": 0})
    return pd.Series({"port": unique[0], "port_conflict_flag": int(len(unique) > 1)})

def locate_and_read_events(path, sheet_name):
    raw = pd.read_excel(path, sheet_name=sheet_name, header=None)
    header_row = None
    for i, row in raw.iterrows():
        vals = row.astype(str).str.lower().tolist()
        if any("operations" in v for v in vals) and any("location details" in v for v in vals):
            header_row = i
            break
    if header_row is None:
        # 对类似 Sheet1 的结构，首行已经近似是表头；正式脚本应在这里加入 sheet-specific 兜底映射。
        raise ValueError("未找到包含 Operations 与 Location Details 的表头行")

    df = pd.read_excel(path, sheet_name=sheet_name, header=header_row)
    df = df.dropna(how="all").copy()
    df.columns = [str(c).strip() for c in df.columns]
    return df

events = locate_and_read_events(INPUT_XLSX, SOURCE_SHEET)

# 统一列名：正式脚本应根据实际 sheet 增补映射。
rename_map = {
    events.columns[0]: "vessel_raw",
    "Operations": "operation",
    "Start": "start_raw",
    "End": "end_raw",
    "Duration": "duration_raw",
    "± Draught": "draught_raw",
    "Location Details": "location_details",
}
events = events.rename(columns={k: v for k, v in rename_map.items() if k in events.columns})

if "transaction_id" not in events.columns:
    new_tx = events["vessel_raw"].notna()
    events["transaction_id"] = new_tx.cumsum()

events["vessel_raw"] = events["vessel_raw"].ffill()
events[["vessel_name", "imo", "vessel_type", "service_status", "dwt", "gt"]] = events["vessel_raw"].apply(parse_vessel)
events["start_dt"] = parse_datetime_series(events["start_raw"])
events["end_dt"] = parse_datetime_series(events["end_raw"])
events["draught_numeric"] = (
    events["draught_raw"].astype(str).str.extract(r"([+-]?\d+(?:\.\d+)?)", expand=False).astype(float)
)

# 交易层基本时间。
tx_time = events.groupby("transaction_id").agg(
    start_dt=("start_dt", "min"),
    end_dt=("end_dt", "max"),
).reset_index()
tx_time["start_round"] = tx_time["start_dt"].apply(round_to_hour)
tx_time["end_round"] = tx_time["end_dt"].apply(round_to_hour)
tx_time["startdate"] = tx_time["start_round"].dt.strftime("%Y-%m-%d")
tx_time["starthour"] = tx_time["start_round"].dt.hour
tx_time["enddate"] = tx_time["end_round"].dt.strftime("%Y-%m-%d")
tx_time["endhour"] = tx_time["end_round"].dt.hour
tx_time["duration"] = ((tx_time["end_dt"] - tx_time["start_dt"]) / pd.Timedelta(hours=1)).round().astype("Int64")

# 港口。
tx_port = (
    events.groupby("transaction_id", group_keys=False)
    .apply(lambda g: choose_transaction_port(g["location_details"]))
    .reset_index()
)

# STS 长表与宽表。
sts = events[events["operation"].astype(str).str.contains("STS", case=False, na=False)].copy()
sts = sts.sort_values(["transaction_id", "start_dt", "end_dt"])
sts["sts_no"] = sts.groupby("transaction_id").cumcount() + 1
sts["supplier"] = sts["location_details"].apply(extract_supplier)
sts["start_STS"] = sts["start_dt"].apply(round_to_hour)
sts["end_STS"] = sts["end_dt"].apply(round_to_hour)
sts["duration_STS_i"] = ((sts["end_dt"] - sts["start_dt"]) / pd.Timedelta(hours=1)).round().astype("Int64")
sts.to_excel(OUT / "sts_episode_long.xlsx", index=False, sheet_name="sts_episode_long")

wide_parts = []
for value_col, prefix in [
    ("supplier", "supplier"),
    ("start_STS", "start_STS"),
    ("end_STS", "end_STS"),
    ("duration_STS_i", "duration_STS"),
]:
    w = sts.pivot(index="transaction_id", columns="sts_no", values=value_col)
    w.columns = [f"{prefix}{int(c)}" for c in w.columns]
    wide_parts.append(w)
sts_wide = pd.concat(wide_parts, axis=1).reset_index()

sts_summary = sts.groupby("transaction_id").agg(
    supplier_n=("sts_no", "max"),
    duration_STS=("duration_STS_i", "sum"),
    final_end_dt=("end_dt", "max"),
).reset_index()
sts_summary["final_end_round"] = sts_summary["final_end_dt"].apply(round_to_hour)
sts_summary["end_STS_final"] = sts_summary["final_end_round"].dt.strftime("%Y-%m-%d")
sts_summary["endhour_STS_final"] = sts_summary["final_end_round"].dt.hour
sts_summary = sts_summary.drop(columns=["final_end_dt", "final_end_round"])

# 交易层船舶字段。
vessel_cols = ["transaction_id", "vessel_name", "imo", "vessel_type", "service_status", "dwt", "gt"]
tx_vessel = events[vessel_cols].drop_duplicates("transaction_id")

transactions = (
    tx_vessel
    .merge(tx_time, on="transaction_id", how="left")
    .merge(tx_port, on="transaction_id", how="left")
    .merge(sts_summary, on="transaction_id", how="left")
    .merge(sts_wide, on="transaction_id", how="left")
)

transactions.to_excel(OUT / "transactions_clean.xlsx", index=False, sheet_name="transactions_clean")
transactions[transactions["port"].isna()].to_excel(
    OUT / "unmatched_ports.xlsx", index=False, sheet_name="unmatched_ports"
)
transactions[transactions["port_conflict_flag"].eq(1)].to_excel(
    OUT / "port_conflicts.xlsx", index=False, sheet_name="port_conflicts"
)
代码框架说明：上方是可执行框架，不是最终生产脚本。正式脚本需要根据实际采用的 sheet 补齐列名映射和去重逻辑；尤其是 Sheet1 这类已有 transaction_id 但表头不规则的 sheet，应单独写入读取映射。

6. Stata 可执行步骤：开放时长与预报开放时长

Stata 阶段从 Python 输出的交易层 .xlsx 文件中取 transaction_id、startdate、starthour、port。以该 date-hour-port 为锚点，计算前后 6、12、24 小时窗口内的开放时长，并将结果输出为 .dta 文件。

窗口口径：本文档采用中心窗口且包含锚点小时，即 abs(obs_hour - transaction_start_hour) <= 6、<= 12、<= 24。若要求严格的前后各 6 小时但不包含端点，应在 do-file 中把条件改为 < 6 等。

6.1 历史锚地开放状态：生成 openhour_6、openhour_12、openhour_24

version 17
clear all
set more off

global ROOT "."
global OUT  "outputs"
capture mkdir "$OUT"

* 1. 读取 Python 输出的交易层 xlsx 数据。
import excel "$OUT/transactions_clean.xlsx", sheet("transactions_clean") firstrow clear
keep transaction_id port startdate starthour
drop if missing(transaction_id)

gen start_td = daily(startdate, "YMD")
format start_td %tdCCYY-NN-DD
destring starthour, replace force
gen anchor_tc = dhms(start_td, starthour, 0, 0)
format anchor_tc %tc

tempfile tx tx_ids
save `tx', replace
keep transaction_id
duplicates drop
save `tx_ids', replace

* 2. 整理小时级锚地开放数据。
use "锚地开放.dta", clear
gen obs_tc = dhms(date_numeric, hour, 0, 0)
format obs_tc %tc
gen open = (status == "Open")
keep port obs_tc open
tempfile anch_open
save `anch_open', replace

* 3. 按 port join，并计算交易开始前后窗口内的开放小时数。
use `tx', clear
drop if missing(port)
joinby port using `anch_open'
gen diff_h = (obs_tc - anchor_tc) / (1000 * 60 * 60)

foreach w in 6 12 24 {
    gen open_in_`w' = open * (abs(diff_h) <= `w')
}

collapse ///
    (sum) openhour_6  = open_in_6 ///
          openhour_12 = open_in_12 ///
          openhour_24 = open_in_24, ///
    by(transaction_id)

tempfile hist_open
save `hist_open', replace

* 4. 保留全部 transaction_id；无法匹配的交易开放小时为空值，便于后续检查。
use `tx_ids', clear
merge 1:1 transaction_id using `hist_open', nogen
save "$OUT/openhour_history.dta", replace

6.2 气象预报开放时长：生成六个 forecast 变量

气象预报开放时长需要两套规则：

  • v1：气象指数 1 视为不开放，2、3、4 视为开放。
  • v2：按 Average closure frequency 转为开放概率。MIO=1 开放概率 28%，MIO=2 为 73%，MIO=3 为 87%，MIO=4 为 88%。窗口内开放时长为开放概率的小时加总。
version 17
clear all
set more off

global ROOT "."
global OUT  "outputs"
capture mkdir "$OUT"

* 1. 交易锚点。
import excel "$OUT/transactions_clean.xlsx", sheet("transactions_clean") firstrow clear
keep transaction_id port startdate starthour
drop if missing(transaction_id)

gen start_td = daily(startdate, "YMD")
format start_td %tdCCYY-NN-DD
destring starthour, replace force
gen anchor_tc = dhms(start_td, starthour, 0, 0)
format anchor_tc %tc

tempfile tx tx_ids
save `tx', replace
keep transaction_id
duplicates drop
save `tx_ids', replace

* 2. 整理气象预报数据。
use "气象预报.dta", clear
capture rename 气象指数 mio
capture confirm numeric variable mio
if _rc {
    destring mio, replace force
}

gen obs_tc = dhms(date_numeric, hour, 0, 0)
format obs_tc %tc

* v1: 1 = closed, 2/3/4 = open。
gen open_v1 = inlist(mio, 2, 3, 4)

* v2: 使用 Average closure frequency 的开放概率。
gen open_v2 = .
replace open_v2 = 0.28 if mio == 1
replace open_v2 = 0.73 if mio == 2
replace open_v2 = 0.87 if mio == 3
replace open_v2 = 0.88 if mio == 4

keep port obs_tc open_v1 open_v2
tempfile forecast
save `forecast', replace

* 3. 按 port join，并计算各窗口 forecast open hours。
use `tx', clear
drop if missing(port)
joinby port using `forecast'
gen diff_h = (obs_tc - anchor_tc) / (1000 * 60 * 60)

foreach w in 6 12 24 {
    gen openf_v1_in_`w' = open_v1 * (abs(diff_h) <= `w')
    gen openf_v2_in_`w' = open_v2 * (abs(diff_h) <= `w')
}

collapse ///
    (sum) openhourf_6_v1  = openf_v1_in_6 ///
          openhourf_12_v1 = openf_v1_in_12 ///
          openhourf_24_v1 = openf_v1_in_24 ///
          openhourf_6_v2  = openf_v2_in_6 ///
          openhourf_12_v2 = openf_v2_in_12 ///
          openhourf_24_v2 = openf_v2_in_24, ///
    by(transaction_id)

tempfile forecast_open
save `forecast_open', replace

* 4. 保留全部 transaction_id。
use `tx_ids', clear
merge 1:1 transaction_id using `forecast_open', nogen
save "$OUT/openhour_forecast.dta", replace

6.3 合并回交易层主表

version 17
clear all

global OUT "outputs"

import excel "$OUT/transactions_clean.xlsx", sheet("transactions_clean") firstrow clear

merge 1:1 transaction_id using "$OUT/openhour_history.dta", nogen

7. 可审查执行清单

交易清洗审查

  • 原始有效事件行数是否与读取日志一致。
  • 交易数是否等于非空 vessel 行数或源 transaction_id 去重数。
  • vessel 字段解析失败样本是否可解释。
  • 重复交易删除前后的数量和 key 是否可追溯。

时间审查

  • 随机抽查 startdate/starthour 与原始最早 Start。
  • 重点测试 23:30 之后跨日四舍五入。
  • duration 是否等于原始最晚 end 与最早 start 的小时差四舍五入。
  • Stata 中 startdate 是否能稳定转为 %td。

STS 与 supplier 审查

  • sts_episode_long.xlsx 行数是否等于原始 STS 行数。
  • supplier_n 合计是否等于 STS episode 数。
  • 同一 supplier 多条 STS 是否被重复记录为 supplier1、supplier2 等。
  • duration_STS 是否等于各 duration_STS* 加总。

港口审查

  • At Zhoushan Xiazhimen Sou 等缩写是否匹配为 条帚门。
  • 未匹配港口样本是否主要为非对照表锚地。
  • 多港口冲突交易是否进入 port_conflicts.xlsx。
  • 最终 port 取值是否只包含 条帚门、秀山东、虾峙门、衢山、马峙 或空值。

Stata 匹配审查

  • 交易层 port 与两个 .dta 中 port 取值完全一致。
  • join 后每笔交易在窗口内的理论最大小时数符合口径：±6 为最多 13 个小时点，±12 为最多 25 个，±24 为最多 49 个。
  • 无法匹配的交易是否由 port 空值、日期超出外部数据范围或港口名不一致造成。
  • v2 开放小时为概率和，因此可以是小数；v1 与历史开放小时为整数。

最终交付审查

  • transactions_clean.xlsx 可独立复现交易层字段。
  • openhour_history.dta 和 openhour_forecast.dta 均保留 transaction_id。
  • transactions_with_openhours.dta 包含全部目标变量。
  • QA 报告列明输入行数、输出交易数、缺失和异常样本。

8. 建议最终产物

产物 生成工具 用途
outputs/transactions_clean.xlsx Python 交易层清洗主表，作为 Stata 匹配输入。
outputs/sts_episode_long.xlsx Python 每条 STS episode 的长表，便于核查多 supplier 与多 STS。

outputs/openhour_history.dta Stata 历史开放状态计算结果：openhour_6、openhour_12、openhour_24。
