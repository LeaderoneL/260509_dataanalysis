Data Sources

数据源说明

🚢

Bunkering Record v3.xlsx

船加油原始记录（修正版 v3）。每次 vessel 信息出现代表一笔新交易；每笔交易含多条 Anchorage（排队等待）和/或 STS-Bunkering（加油）记录。

10 列 · ~4400 行

⚓

锚地开放.dta

港口锚地开放状态数据。记录 date-hour-port 维度的 status（Open / Closed），原因列 original_reason 记录关闭原因（如"风浪大"）。根据极端 case 回查原始数据后修正。

5 列 (port, hour, status, original_reason, date_numeric) · 76,680 行 · 5 港口

🌤

气象预报.dta

港口气象预报指数数据。记录 date-hour-port 维度的 气象指数（1/2/3/4，从坏到好），用于计算交易开始前后港口预报开放时长。

4 列 · 71,976 行

Stage 1

第一步：预处理（时间标准化 + 字段解析）

PDF 原始要求 补充要求

1.0 数据修正 v3

根据一次处理中发现的极端 case，回查原始数据检查错误，对收集的数据做了修正（此处略去修正细节），使用修正后的 Bunkering Record v3.xlsx 作为输入重新运行全流程。

1.1 Transaction ID 分配

原始数据无 transaction ID 列。以 vessel 列出现非空值作为新 transaction 的边界标记，为每一行分配递增的整数 transaction_id。

1.2 Vessel 信息提取

对 vessel 列进行向前填充（forward fill）。从 vessel 文本字符串中正则提取以下字段：

字段说明示例
vessel_name船名JOLLY ARGENTO
vessel_code船舶代码（IMO 号）9467043
vessel_type船舶类型Container Ship (Fully Cellular)
vessel_status服役状态In Service/Commission
dwt载重吨位62510
gt总吨位47789

1.3 时间标准化

原始数据存在 两种 时间格式，需要统一解析为 datetime：

格式 A：2023-01-30 04:15:00（datetime 对象）

格式 B：02 Feb 2023 08:11（文本字符串）

解析结果统一存储为 YYYY-MM-DD HH:MM:SS，同时生成格式化日期字符串（DD Mon YYYY）和小时数（四舍五入）。

1.4 小时四舍五入修正 v3 修正

问题：如 2024/1/5 23:42 → 被近似为 2024/1/5 0:00（同日 0 点），实际应为 2024/1/6 0:00（次日 0 点）。

修正：分钟 ≥ 30 时小时 +1，若小时变为 24 则翻日为次日 0 点，并同步更新日期。

1.5 Duration 解析

解析 duration 文本为数字小时（四舍五入）。支持 "X day(s) Y h Z min" 等多种格式；特殊值 "-" 表示 0 小时。

1.6 Draught 解析

从 draught 文本中提取数值（如 "0 m" → 0.0, "-0.5 m" → -0.5）。

1.7 Port 匹配 PDF 补充

从 Anchorage 行的 Location Details 匹配对照表，支持 Excel 截断模糊匹配：

关键字匹配端口关键字匹配端口
Tide and Berth秀山东Qushan / Qushan Bunkering衢山
Xiazhimen South条帚门Mashi / Mazhi马峙
Xiazhimen North虾峙门——

多港口规则：同一交易有多个港口时，优先使用匹配对照表的港口；无法匹配的 port 留空并记录到 unmatched_port。

1.8 Supplier 提取

从 STS 行的 Location Details 提取 supplier 名称（去掉 "With " 前缀）。清洗 \xa0 不间断空格。

1.9 预处理输出

输出 bunkering_preprocessed.xlsx，28 列，保留所有行级字段（解析后的 datetime、标准化时间、port_matched、supplier 等），供后续处理使用。

Stage 2

第二步：交易级别聚合

PDF 原始要求 补充要求 v3 新增

2.1 整体时间线

按 transaction_id 分组，取所有行的最早 start 和最晚 end：

输出列说明示例
startdateDD Mon YYYY 格式25 Jan 2023
starthour开始小时（四舍五入）17
enddateDD Mon YYYY 格式30 Jan 2023
endhour结束小时（四舍五入）14
duration总时长（小时，四舍五入）117

2.2 多 STS 展开 补充 v3 修正

按 不重复的 supplier 进行聚合展开（非每次加油事件）。同一 supplier 在该交易中多次加油时，聚合为一条记录：start 取最早开始时间，end 取最晚结束时间，duration 为各次加油时长之和。supplier 按首次出现时间排序。动态展开为 N 组列（N 取所有交易中不重复 supplier 数量的最大值，当前为 5）。

Columns (i = 1..N)说明
supplier{i}第 i 个加油 supplier 名称
start_STS{i}开始日期（DD Mon YYYY）
starthour_STS{i}开始小时（四舍五入）
end_STS{i}结束日期（DD Mon YYYY）
endhour_STS{i}结束小时（四舍五入）
duration_STS{i}第 i 次 STS 加油时长（小时）

最后加总为 duration_STS。

2.3 新增变量 v3 新增

🔢

supplier_n

本次 transaction 一共出现了多少个不重复的 supplier。通过对同一交易的所有 STS 行进行 supplier 去重计数得到。

⏱

end_STS_final / endhour_STS_final

记录最后一个 supplier 加油的日期和小时。即按时间排序后的最后一次 STS 结束时间，用于分析最终加油完成时刻。

2.4 Port 与 Draught

port：从 Anchorage 行匹配对照表，优先取成功匹配的；无匹配留空。unmatched_port：记录无法匹配的锚地原始文本。draught：取该交易所有行 draught 数值均值。

2.5 去重

删除除 transaction_id 外其他列完全相同的重复 transaction 记录。

2.6 输出

输出 3_bunkering_final.xlsx（Python 脚本 C2_finalize_bunkering.py），每行一笔交易。列结构：15 base (含 supplier_n, end_STS_final, endhour_STS_final) + 6N STS (N=5, max unique suppliers) + 4 trailer = 共 49 列。

Stage 3

第三步：外部数据匹配 新增需求

使用 Stage 2 输出的 startdate、starthour、port 与两份外部数据按 date-hour-port 进行匹配，计算交易开始时间前后不同时间窗口的港口开放时长。

3.1 匹配锚地开放数据（锚地开放.dta）

📋

数据结构

5 列：port(str9), hour(byte 0-23), status("Open"/"Closed"), original_reason(关闭原因，如"风浪大"), date_numeric(%td 日期)。76,680 行覆盖 5 港口。

🔗

匹配键

startdate + starthour + port（按交易开始时刻所在 date-hour-port 定位）

📐

时间窗口

前后 ±6h、±12h、±24h 三个窗口

计算逻辑：对每笔交易，以 startdate-starthour 为中心，展开 ±N 小时窗口（N=6/12/24）内的所有 hour 级行，按 port + date + hour 匹配锚地开放记录，统计窗口内 status == "Open" 的小时数。

匹配率：1,226/1,543（79.5%）。未匹配的交易多为 port 为空或 startdate 在锚地数据时间范围外。

输出变量含义
openhour_6start 前后 ±6h 窗口锚地开放时长
openhour_12start 前后 ±12h 窗口锚地开放时长
openhour_24start 前后 ±24h 窗口锚地开放时长

3.2 匹配气象预报数据（气象预报.dta）

🌤

数据结构

date-hour-port 维度。气象指数：1 → 4（从坏到好）

🔗

匹配键

startdate + starthour + port

🧪

两种开放判定

Version 1：阈值法 | Version 2：平均值法

Version 1 — 阈值开放判定

默认 1 = 不开放（closed），2 / 3 / 4 = 开放（open）。按此规则统计窗口内开放小时数。

Version 2 — 平均值法开放判定

基于各港口各气象指数的 historical closure frequency（关闭频率），计算某小时预报开放的期望概率：

气象指数 k 对应的小时开放概率 = 1 - closure_frequency(port, k)

窗口开放时长 = ∑ [1 - closure_frequency(port, weather_index_hour_i)]（对窗口内每个小时 i）

closure frequency 来源：由于未提供独立的 closure frequency 表，当前实现从气象预报数据中经验性地计算各港口各气象指数的关闭频率：closure_freq(port, k) = P(气象指数 == 1 | port, k)。即对于每个 (port, weather_index) 组合，统计 weather_index == 1（关闭）的比例作为 closure frequency。气象预报数据匹配率：1,239/1,543（80.3%）。

输出变量总览

变量版本含义
openhourf_6_v1V1 阈值法±6h 窗口预报开放时长（1=关, 2/3/4=开）
openhourf_12_v1V1 阈值法±12h 窗口预报开放时长（1=关, 2/3/4=开）
openhourf_24_v1V1 阈值法±24h 窗口预报开放时长（1=关, 2/3/4=开）
openhourf_6_v2V2 平均值法±6h 窗口预报开放时长（1 - closure_freq 加权）
openhourf_12_v2V2 平均值法±12h 窗口预报开放时长（1 - closure_freq 加权）
openhourf_24_v2V2 平均值法±24h 窗口预报开放时长（1 - closure_freq 加权）
